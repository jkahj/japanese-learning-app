## Architecture

### Firestore Schema
```
users/{uid}/data/wordData   → entire userData object (SRS progress, srsLevel, nextReview, status)
users/{uid}/data/seenWords  → jp_seen_v2 rotation state { lvKey, seen:[…], cycle }
users/{uid}/data/promoted   → { arr: [ …full VOCAB entries… ] }
```

3 documents per user. 3 reads on sign-in, 1 batched write per change event.

### Sync Strategy
| Layer | Role |
|---|---|
| In-memory `userData` | Instant reads — always from memory |
| `localStorage` | Offline cache — written on every change |
| Firestore | Source of truth — debounced 2 s batch write |

On sign-in: Firestore → merge into memory + localStorage (cloud wins on conflict).
On data write: memory + localStorage immediately → Firestore after 2 s idle.

### Security Rules (firebase-rules.txt)
Each signed-in user can only read/write `users/{theirUID}/data/*`. Everything else is denied.

## Sync Hooks in index.html

```js
// saveStorage — fires on every setWD() call
function saveStorage(data) {
  localStorage.setItem('jp_data', JSON.stringify(data));
  if (window.FB) FB.syncWordData(data);        // ← added
}

// savePromotedList — fires when user adds/removes curated words
function savePromotedList(arr) {
  localStorage.setItem(PROMOTED_KEY, JSON.stringify(arr));
  if (window.FB) FB.syncPromoted(arr);         // ← added
}

// buildDailyWords — fires when rotation advances
  localStorage.setItem('jp_seen_v2', JSON.stringify(seenData));
  if (window.FB) FB.syncSeenWords(seenData);   // ← added
```
