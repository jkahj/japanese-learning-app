### 2. Jisho CORS Fix — Multi-Proxy Fallback
- **Root cause**: Calling `https://jisho.org` from `file://` (and sometimes `localhost`) is blocked by CORS
- **Fix v1**: Two-attempt strategy — direct fetch first, then `api.allorigins.win` proxy
- **Fix v2**: Upgraded to `Promise.any()` racing 4 proxies in parallel (direct, corsproxy.io, allorigins, cors.sh)
- **Fix v3** (final): Expanded to 7 proxies racing in parallel for maximum reliability:

| # | Endpoint | Notes |
|---|---|---|
| 0 | Direct `jisho.org` | Works on HTTP server |
| 1 | `corsproxy.io/?{url}` | Primary proxy |
| 2 | `allorigins.win/raw?url=` | Raw response |
| 3 | `api.codetabs.com/v1/proxy?quest=` | Reliable dedicated proxy |
| 4 | `thingproxy.freeboard.io/fetch/` | Independent provider |
| 5 | `corsproxy.io/?url=` (encoded) | Alternate corsproxy format |
| 6 | `allorigins.win/get?url=` | JSON wrapper; auto-unwrapped via `j.contents` |

### 3. Search Speed Optimisations
- **Proxy memory**: `_jishoFastProxy` stores the index of the winning proxy — subsequent searches skip the race entirely and go straight to the proven endpoint
- **Result cache**: `_jishoCache[query]` stores results in-memory — re-searching the same word is instant (displays ⚡ in count)
- **Debounce reduced**: 350ms → 200ms (safe since cache hits are near-instant)
- **Per-attempt timeout**: Each proxy gets its own `AbortController` with 9s timeout (7s on fast path)

## Architecture Notes
```
jishoFetch(query)
  ├─ Fast path: _jishoFastProxy !== null → single fetch to known-good proxy
  │    └─ on failure: clear _jishoFastProxy → fall through to race
  └─ Slow path: Promise.any([7 proxies]) → remember winner index
        └─ _tryJishoUrl(url, opts, timeout) handles AbortController + allorigins unwrap
```
