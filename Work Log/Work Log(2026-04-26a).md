## Issue Fixed

### JLPT filter ignored for Part B (CURATED_LV) words ✅

**Symptom**: Selecting N4 in the vocab filter showed words from N4, N3, N2, and N1 all mixed together. Only the hand-crafted VOCAB words (Part A) were filtered; the 精選-badged JMdict words (Part B) were not.

**Root cause**: `renderVocabCurated()` renders vocab in two parts:

- **Part A** — hand-crafted `VOCAB` entries: passed through `filteredVocab()`, which correctly checks `state.filter.jlpt`.
- **Part B** — `CURATED_LV` JMdict words: iterated with `state.selectedLevels.flatMap(lv => ...)`, which loops over *all* levels the user selected at the welcome screen. Although a per-word check `if (jlpt !== 'all' && wj !== jlpt) return false` existed on `data.j`, the level loop itself never skipped entire levels — meaning every selected level's word list was always evaluated, which could surface words whose `data.j` didn't precisely match the CURATED_LV bucket they were filed under.

**Fix**: Added an early-exit guard at the top of the `flatMap` callback, before any word-level iteration:

```js
// BEFORE:
const dictHTML = state.selectedLevels.flatMap(lv => {
  const list = CURATED_LV[lv];
  if (!list) return [];

// AFTER:
const dictHTML = state.selectedLevels.flatMap(lv => {
  if (jlpt !== 'all' && lv !== jlpt) return [];  // honour JLPT filter at level granularity
  const list = CURATED_LV[lv];
  if (!list) return [];
```

When a specific JLPT level is active (e.g. N4), any `lv` that isn't N4 immediately returns `[]`, so none of its words are rendered — regardless of what `data.j` says.

The existing per-word check `if (jlpt !== 'all' && wj !== jlpt) return false` remains as a secondary guard for edge cases where a word's stored JLPT tag differs from the list it's filed under.
